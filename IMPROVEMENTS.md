## Коды гейта (что чинить)

- `prob.found.req` 686, `cant.apply.symbols` 211 — несогласованность типов после вывода.
- `cant.deref` 188 — неизвестен тип возврата обфусцированных вызовов.
- `void.not.allowed.here` 167 — void-вызов используется как значение.
- `ref.ambiguous` 133 — возможно, побочка переименования (одноимённые типы).
- `array.req.but.found` 47 — типы массивов (известный gap).
- `is.preview` 100 — preview-фичи Java 28, не дефект декомпилятора.

## Варианты (по приоритету)

1. **Флаг `--no-rename` + A/B гейта.** Пропускать `ClassRenamer.build`, сравнить
   bad/real с переименованием и без. Цель — отделить +31 bad от ренеймера.
   Ожидание: быстрый ответ, нужен ли откат/ограничение ренеймера.
2. **Убрать void-как-значение (167 ошибок).** Резолвить вызываемый метод через
   `ClassHierarchy`; если дескриптор возвращает `V` — не пушить вызов в стек,
   эмитить `ExprStmt`. Ожидание: −100…150 ошибок гейта.
3. **Типизировать возвраты вызовов через иерархию** (`cant.deref` 188,
   `cant.apply.symbols` 211): для `INVOKE` искать метод по owner+name+desc в jar и
   брать тип возврата; закрывает обфусцированные имена без нативного ключа.
4. **Проверить `ref.ambiguous` 133** — если это следствие переименования, добавить
   защиту от конфликта простого имени с внешними типами (`Sound`, `World` и т.п.).
5. **Массивы (`array.req` 47)** — отложенный gap: нужна трассировка значения под
   `aastore` (см. `STATUS.md`, known gaps).
6. **`is.preview` 100** — не наш дефект; для гейта имеет смысл помечать такие
   классы как «preview», а не bad.

## Диагностика s180: `cant.deref` — это переиспользование слотов

Пример `net/Spacevisuals61`: параметр объявлен `int p2`, а в теле печатается
`p2.comp_4801()`. Слот 2 переиспользован под объект, но имя у нас одно на слот —
отсюда «int cannot be dereferenced». То же в `world/Method`, `net/ClientHandler`.

Значит типизация возвратов тут не поможет: нужен **slot versioning** — отдельное имя
для версии слота при смене вида (примитив ↔ ссылка), как уже сделано для
«массив + примитив» (s126). План: расширить `collectSlotSegments`/`SPLIT_SLOTS` на
пары «ссылка/примитив», версии `_o`, объявления — через механизм ARRAY_DECLS.

Оценка: средняя правка в `TypeInference` + `BytecodeToExpr`; риск — рост числа
переименований и новые ошибки типов, поэтому обязателен замер гейта на SpaceVisuals
и slash-obf с откатом при регрессе.

**Результат s180:** конфликт расширен до «примитив + любая ссылка» (версия `_a`,
`Object`), приёмник-переменная кастуется к владельцу метода. SpaceVisuals:
bad 260 → **257**, real 142 → **128**, `cant.deref` 179 → **31**, `array.req` 40 → 29,
`prob.found.req` 672 → 586; slash-obf: bad 58 → **56**, real 14 → **7**. Регрессий нет.

## Диагностика s181: пересмотр варианта 1 (типизация возвратов)

**Проверено (гейт SpaceVisuals с текстами ошибок javac):** из 134 сэмплов `prob.found.req`
**72 — «incompatible types: int cannot be converted to boolean»**. Тип возврата вызова уже
берётся из `m.desc` (BytecodeToExpr:1084), поэтому «искать метод по owner+desc, брать тип
возврата» почти ничего не даст. Настоящая дыра — **потеря признака Z** по пути
«invoke → phi-темп → return/условие» (пример `mod/Spacevisuals21.active()`: boolean-метод,
но `t4_0` объявлен `int`). Остаток (86) — `Object cannot be converted to T` (инвок
возвращает объект, локал/темп остаётся `Object`).

**Результат s181 (Z-перенос):** `normalizeBooleanLiterals(res, boolReturn)` — переменная
из `Ast.Return` в boolean-методе сеет цепочку boolean-темпов (3-раундовый promotion,
литералы 0/1 → false/true). SpaceVisuals: bad 257 → **222**, real 128 → **129**
(переклассификация), `prob.found.req` 323 → **86**, survived 4514 без изменений;
slash-obf: bad 56 → **38**, real 7 без изменений. Регрессий нет.

**Дальше по остатку `prob.found.req` (86):** `Object cannot be converted to T` — типизация
локалов/темпов на объектные типы из возврата вызова (как для массива в normalizeArrayTemps,
но для Object → объявленный тип). Это следующий шаг, не Z.

## Результат s182: Object→T (типизация object-темпов)

`normalizeObjectTemps(res, retDesc)` — аналог `normalizeArrayTemps` для не-массивных ссылок:
seed из `Ast.Return` (переменная → тип возврата метода), promotion `Object`-темпов из
`Ast.Call.retDesc`-ссылки и не-`Object`-локалов. SpaceVisuals: bad 222 → **208**,
real 129 → **128**, ушло 14 bad-классов (`mod/Cls`, `util/Global`, `util/Offer` и др.),
survived 4514 без изменений; slash-obf: bad 38 → **30**, real 7. Регрессий нет.

**Остаток `prob.found.req` (после s182):** остаточные нерезолвимые типы/перегрузки; конкретный
новый шаг — смотреть оставшиеся bad-классы по текстам ошибок в гейте.
