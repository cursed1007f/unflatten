# Лицензирование Java-декомпилятора (C++ loader)

## Архитектура (обзор)

```
[Клиент Windows]                    [Сервер (VPS)]
+---------------------+            +------------------------------+
| loader.exe (C++)     |            | activate.py (FastAPI :8000)  |
|  - собирает HWID     |--HTTPS---> |  - ищет ключ в SQLite       |
|  - вводит ключ       |  ?hwid=&   |  - привязывает HWID         |
|  - пишет .lic        |  key=      |  - отдаёт срок              |
|  - проверяет срок    | <--JSON--- |  - отзывает по статусу      |
|  - запускает jar     |            +-----------------------------+
+---------------------+            | key_bot.py  (Telegram)       |
                                   |  - /gen 1m|3m|1y (ключи)     |
                                   |  - /grant <ключ> <ник>       |
                                   |  - /revoke /hwid /total      |
                                   +-----------------------------+
| users_bot.py (Telegram)      |
                                    |  - /users: ник/HWID/срок     |
                                    |  - /find, /expire, /status   |
                                    +-----------------------------+
                                    | notifier_bot.py (Telegram)   |
                                    |  - ТОЛЬКО шлёт уведомления  |
                                    |  о HWID (через notifier.py) |
                                    +-----------------------------+
                                    | license.db (SQLite, общая)   |
                                    +-----------------------------+
```

## Ключевая идея

- **Ключ** — выдает бот `key_bot` на срок 1 мес / 3 мес / 1 год (`/gen 1m|3m|1y`).
  Формат `XXXX-XXXX-XXXX-XXXX` (без похожих `O/0/I/1`).
- **HWID** — собирается лоадером на машине клиента:
  CPU ID, MAC-адрес, серийник диска, серийник материнки, MachineGuid из реестра.
  Всё хешируется в **SHA-256** → 32-символьный hex.
- **Активация** — клиент шлёт `hwid` + `key` на `/activate`. Сервер:
  - ключ не найден/отозван → `invalid_key`
  - срок истёк → `expired`
  - привязан к другому HWID → `wrong_hwid`
  - иначе привязывает HWID к ключу и возвращает `not_before`/`not_after`.
- **Повторный запуск** — лоадер читает локальный `decompiler.lic`, сверяет HWID
  текущей машины с записанным и проверяет, что сейчас внутри срока. Если HWID
  чужой или срок прошёл — отказывается запускать и предлагает ключ заново.

## Что нужно сделать перед продом (важно!)

В `loader/src/activation.cpp` код намеренно упрощён и НЕ готов к продакшену как есть:

1. **TLS**: сейчас флагами `SECURITY_FLAG_IGNORE_*` отключается проверка сертификата.
   В проде **убери эти флаги** и используй валидный TLS-сертификат на сервере.
2. **Подпись запроса**: endpoint `/activate` принимает `hwid`+`key` открыто —
   это позволяет подделке простым повторением запроса. В проде добавь HMAC/подпись:
   `sig = sha256(hwid + ':' + key + ':' + server_secret)`, сервер проверяет sig.
3. **Проверка целостности jar**: лоадер должен проверять SHA-256 самого jar
   (выложи ожидаемый хеш в подписанный файл), чтобы юзер не подменил декомпилятор.
4. **Обфускация/анти-Debug**: HWID-защиту можно обойти узелённым реверсом.
   Для коммерческого порога хватит, но если важно — добавь упаковку/швы.

## Сборка GUI-лоадера

GUI-версия — тёмно-синее окно с плавными анимациями (пульс-индикатор, hover на
кнопке, градиентный фон, скруглённые карточки). Собирается тем же MinGW:

```bash
g++ -std=c++17 -O2 -I src src/gui_main.cpp src/gui.cpp src/hwid.cpp \
    src/license.cpp src/activation.cpp -municode -o loader-gui.exe \
    -lws2_32 -liphlpapi -lwinhttp -lshell32 -lcomctl32 -lgdi32
```

Запуск: `loader-gui.exe`. Логика та же, что у консольной версии: HWID → локальная
проверка подписки → (при необходимости) ввод ключа и активация → запуск jar.

## Запуск сервера

```bash
cd loader/server
pip install -r requirements.txt

export KEYBOT_TOKEN="..."     # токен бота, который генерирует ключи
export USERSBOT_TOKEN="..."   # токен бота, который показывает юзеров
export HWIDBOT_TOKEN="..."  # бот-уведомитель HWID
export HWIDBOT_ADMIN="1900123071"  # ваш chat_id — сюда шлют уведомления

python key_bot.py &           # бот генерации ключей
python users_bot.py &         # бот юзеров/HWID
python notifier_bot.py &      # бот-уведомитель о HWID (только отправка)
uvicorn activate:app --host 0.0.0.0 --port 8000 &
```

Если идёт за reverse proxy (Nginx) с TLS — пробрось `/activate` на `127.0.0.1:8000`.

## Как создать бота-уведомителя (HWID) — пошагово

Это быстрый один бот «только шлёт уведомления о HWID». Вам нужен только
ТЕЛЕГРАМ и VPS/компьютер, где крутится `activate.py`.

1. В Telegram найдите **@BotFather** и отправьте `/newbot`.
2. Бот спросит имя — введите например `JavaDecHWID`.
3. Бот спросит username (оканчивается на `bot`) — например `javadec_hwid_bot`.
4. BotFather вернёт **токен** вида `123456789:AA...` — скопируйте его.
5. Напишите вашему новому боту `/start` (чтобы у него появился ваш чат).
6. На сервере: `export HWIDBOT_TOKEN="<токен>"`.
   Чтобы точно узнать свой chat_id, запустите `python notifier_bot.py`,
   нажмите `/start` в боте — он напишет `Ваш chat_id: <число>`.
   По умолчанию уже стоит ваш id: `1900123071`.
7. `export HWIDBOT_ADMIN="1900123071"` и запустите `python notifier_bot.py`.

Готово: при каждой активации (`/activate`) в бот-уведомитель придёт сообщение
с HWID, ключом, владельцем и сроком действия.

## Боевой сценарий (через Telegram)

1. Продавец: `/gen 3m` в `key_bot` → бот выдаёт ключ `XXXX-...`.
2. Продавец: `/grant XXXX-... @username` — запомнить, кому выдан.
3. Клиент: `loader.exe` → видит, что подписки нет → показывает HWID →
   вводит ключ → лоадер шлёт `/activate` → сервер привязывает HWID и отдаёт срок →
   лоадер сохраняет `decompiler.lic` и запускает `jar`.
4. Продавец: `/users` в `users_bot` → список всех: ник / hwid / срок / статус.
5. Отзыв: `/revoke <ключ>` в `key_bot` → следующий запуск клиента вернёт `invalid_key`.

## Примечания по безопасности

- Ключи в БД хранятся в открытом виде. Если база утечёт — злоумышленник получит
  валидные ключи. Для коммерции лучше хранить `sha256(key)` и отдавать ключ
  клиенту только при генерации.
- Просрочка: сервер возвращает `expired` и отказывает; локальная копия тоже
  проверяет `not_after`. Но локальную проверку можно обойти правкой файла —
  отсюда важность серверной проверки в проде (режим онлайн).
- Много ключей на один HWID не запрещено — решайте политику (например, блок
  после N активаций или привязка "1 HWID = 1 подписка").
