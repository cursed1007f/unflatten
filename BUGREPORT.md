# Багрепорт: известные артефакты декомпилятора

Автономный список известных несовершенств вывода `--ast`. Здесь не про CFF
(он разворачивается — см. `CFF.md`), а про остатки эмиттера, которые остаются
в сгенерированном Java-коде после де-флаттенинга. Метрики собраны на джарке
`slashvisuals-test-obf.jar` (версия DeepSeek, 16.11.2026 20:37, 56.4 МБ; `--detect`
→ `CFF_TABLESWITCH`, 39 794 метода).

---

## Приоритетные (влияют на читаемость)

### 1. Контекстный `>= this` — 8 мест (требует контекстной типизации)

Пример:
```java
if (iVar29 >= this) { ... }        // right: слот 0 как this, но это int
if (this >= this.size()) { ... }   // left: this в int-сравнении
if (oVar4.length() >= this) { ... }
```

**Причина.** Обфускатор переиспользует слот 0 под int-временную наряду с `this`
(объект). `VarNameResolver.name()` называет слот 0 instance-метода `this`, если его
тип — объект (правки `NameResolver` + `classifyPrimitiveStores` в `TypeInference`
починили статический случай индексов `new double[this]`, `arr[this]`). Но в этих 8
местах объектный слот 0 участвует в **int-сравнении после де-флаттенинга** (спил
переиспользовал слот) — статическая типизация слота не дотягивается.

**План.** Контекстная типизация (резолв имени по типу операнда в операции, SSA-уровень),
а не по статическому `slotTypes`.

### 2. `this`-путаница в unwind-последовательности — часть `[this]`

После первой правки `[this]` ушло с 21 до 10, `new...[this]` с 12 до 1. Осталось ~10
мест, где `this` печатается в индексе/разыменовании из-за спилл-сдвига слотов.
Тот же корень, что п.1.

## Косметика (читаемо, но не идеально)

### 3. `throw(oVarN)` из catch-переменной

```java
catch (java.lang.Throwable e) { oVar3.close(); oVar4 = 0; }
...
throw(oVar4);
```
Дефолтная ветвь unwind-последовательности; корректно по факту, но имя `oVarN`
вместо исходного exception.

### 4. «Глухое» ветвление после ресурса

```java
if (oVar2 == null) { throw(oVar3); } else { oVar2.close(); }
```
де-флаттенинг оставляет явную проверку, которую исходный код держал неявно.

### 5. `return 0;` — 1227

Методы-заглушки/ранние выходы, печатаются литералом вместо `return <var>;`.

### 6. `super()`/`this()` печатаются как `this.<init>()`

Конструкторы выводятся как `oVar0.<init>()` вместо `super(...)`/`this(...)`.

## Некритично / известный задел

- Локальные не объявляются (код читается, но не компилируется сам по себе —
  на КОМПИЛЯЦИЮ это не заявлено).
- invokedynamic-строки (StringConcatFactory) и лямбды не развёрнуты.
- Types/generics для коллекций не подставляются.
- `iVar != 0`-формы boolean-остатки в редких местах.

---

## Чекер качества (задел)

Перечисленные маркеры (`>= this`, `[this]`, `throw(0)`, `/* ? */`, `.cast(Object)`,
`new Object(`, `return 0;`, `this.<init>()`) — кандидаты в автоматический чекер:
считать вхождения, бить в балл, гонять в регресс после каждой правки эмиттера.
