# Багрепорт: известные артефакты декомпилятора

Автономный список известных несовершенств вывода `--ast`. Здесь не про CFF
(он разворачивается — см. `CFF.md`), а про остатки эмиттера, которые остаются
в сгенерированном Java-коде после де-флаттенинга. Метрики собраны на джарке
`slashvisuals-test-obf.jar` (комбо: свой RenameCore CFF+OBF-шум; `--detect`
→ `CFF_TABLESWITCH`, 143 292 инструкции, 5348 классов/методов).

Актуальный балл чекера: **12 417** (было 30 572 в начале разбора).

---

## Исправлено (регресс-контроль)

### ✔ `>= this` — 608 → 0

Корень оказался **не** в переиспользовании слота 0, а в том, что эмиттер
**не обрабатывал `GETFIELD`**: `ALOAD 0; GETFIELD f` печатался голым `this`,
значение поля терялось, и `this` прилипал к числовым операциям
(`iVar6 < this`, `new double[this]`, `this != 0`).
Фикс: `case GETFIELD` в `BytecodeToExpr` (`this.field` / `receiver.field`).
Плюс на всякий случай оставлен `SlotZeroResolver` (dataflow по CFG для слота 0) —
страховка на случай реального переиспользования слота под спилл (в текущем
джарке таких методов нет).

### ✔ `[this]` (индексы) — 46 → 0

Следствие того же `GETFIELD`-фикса + уточнение регекса чекера: `[this.field]`
(валидный доступ к члену) больше не считается артефактом.

### ✔ `throw(число/var)` — 65 → 0

`ATHROW` по JVM всегда кидает ссылку на `Throwable`. Если на стеке примитив
(число/primitive-var) — стек испорчен (переиспользованный catch-слот),
настоящий throw-объект потерян. Фикс: такие `ATHROW` не эмитим, блок завершаем.
Чекер сужен: `throw(oVarN)` (валидная ссылка) больше не считается багом.

### ✔ `this.<init>` — 5398 → 0

Две причины:
1. Конструкторный вызов на `this` (`INVOKESPECIAL <init>` на `ALOAD 0`) печатался
   как `this.<init>(...)`. Фикс: рендерим `super(...)` (owner ≠ текущий класс)
   либо `this(...)` (делегирование).
2. Разрывная инициализация обфускатора `new X; astore k; …; aload k; invokespecial
   <init>`. Фикс: отслеживаем «в локале `k` лежит создаваемый `NewObject`»
   (`pendingNew`) и склеиваем в `k = new X(args)`. Остаточный невалидный
   `<init>` на переменной/литерале подавляем (`p0.<init>(...)`, `16.0.<init>(...)`).

### ✔ `return 0` в boolean-методах — часть `return 0`

`IRETURN 0/1` в boolean-методе печатался как `return 0/1`. Фикс: `boolLit` на
`IRETURN` при boolean-возврате → `return false/true`.

### ✔ Мёртвый код после `return`/`throw`

`SEQUENCE`/`LOOP`/`IF_ELSE` дописывали недостижимые блоки-братья после
терминатора. Фикс: `outTerminated()` — не эмитим узлы после `return`/`throw`.

### ✔ Мёртвые `iVar=const` (write-only) — 10 031 → 6083

Пасс `DeadStores`: удаляет присваивания примитив-локалям (`iVar/fVar/lVar/dVar`),
значение которых — литерал, и **имя переменной ни разу не читается** в методе.

## Остаётся

### `return 0;` — 251

Легитимные ранние выходы в `int`/`float`-методах (и заглушки). Это корректно;
массово чистится только с восстановлением возвращаемого выражения, которого в
байткоде уже нет (потеряно при де-флаттенинге). Оставлено как есть.

### «Глухое» ветвление после ресурса

```java
if (oVar2 == null) { throw(oVar3); } else { oVar2.close(); }
```
де-флаттенинг оставляет явную проверку, которую исходный код держал неявно.

### Живые `iVar=const` — 6083

Остаток — **живые** инициализации счётчиков (`iVar10 = 0;` перед
`while (iVar10 < ...)`) и повторные записи в читаемые переменные. Их удалять
нельзя; регекс чекера их не отличает от мёртвых, поэтому метрика включает и их.

## Поведение DeadStores (важно при отладке)

- Пасс **консервативный**: удаляет присваивание, только если имя переменной
  нигде не читается во всём методе (чтения собираются один раз на метод, а не
  по отдельным ветвям/блокам).
- Важно: `Ast.If.elseBranch()`/`Ast.Switch.defaultBranch()` могут быть `null`
  (эмиттер кладёт `null` при пустой ветви). В `DeadStores` обход и перестройка
  узлов это учитывают (`filterList(null) == null`). Ранее отсутствие этой
  защиты давало `NullPointerException` на 269 классах и схлопывание вывода —
  при правках пасса обязательно проверять `--ast` на `// class:` (ошибки) и на
  баланс скобок.
- Пасс подключён в `StructureToAst.convert(...)` (после построения AST метода).

## Некритично / известный задел

- Локальные не объявляются (код читается, но не компилируется сам по себе —
  на КОМПИЛЯЦИЮ это не заявлено).
- invokedynamic-строки (StringConcatFactory) и лямбды не развёрнуты.
- Types/generics для коллекций не подставляются.
- `iVar != 0`-формы boolean-остатки в редких местах.

---

## Чекер качества (регресс-контроль)

`QualityChecker` считает маркеры (`>= this`, `[this]`, `throw(число/var)`,
`/* ? */`, `.cast(Object)`, `new Object(`, `return 0;`, `this.<init>`,
мёртвые `iVar=const`) и сводит в балл (ниже = лучше). Гоняется в `--ast`
(сводка в stderr). Для `>= this` чекер дополнительно печатает в stdout
класс+строку мест (`// QSITE [...]`).
